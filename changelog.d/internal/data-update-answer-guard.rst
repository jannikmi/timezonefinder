an automated data update now states what it changed in answers rather than in bytes: ``scripts/data_update_guard.py`` re-answers a frozen 10,000-point on-land sample against the freshly compiled boundary data and rewrites the committed baseline under ``tests/fixtures/data_update/``, so the update pull request is reviewed as a text diff of timezone names - which survives a binary format change, unlike a comparison against the previously packaged data. An ordinary refinement release moves no answers at all; above a 5 % changed-answer rate ``update_data.sh`` stops rather than preparing a release the pipeline would merge and publish unread, and the weekly job keeps the rejected baseline as an artifact so the diff behind a refusal is still reviewable. The baseline describes the full dataset with oceans, so other ``--dataset`` variants are skipped rather than measured against it. The boundary and hole payload sizes are reported beside it and gate nothing, since the four calibrated releases support no symmetric band for them
