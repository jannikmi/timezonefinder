an automated data update now states what it changed in answers rather than in bytes: ``scripts/data_update_guard.py`` re-answers a frozen 10,000-point on-land sample against the freshly compiled boundary data and rewrites the committed baseline under ``tests/fixtures/data_update/``, so the update pull request is reviewed as a text diff of timezone names - which survives a binary format change, unlike a comparison against the previously packaged data. An ordinary refinement release moves no answers at all; above a 5 % changed-answer rate the release is still prepared, and the weekly job opens it as a draft that nothing merges, so what moved is read as a pull request diff and a person decides rather than the pipeline publishing it unread. The baseline describes the full dataset with oceans, so other ``--dataset`` variants are skipped rather than measured against it. The boundary and hole payload sizes are gated beside it, on a symmetric band per file - 5 % of the boundary payload and 10 % of the hole payload, each about 3.6x the largest move measured across 2025c, 2026a, 2026b and 2026c converted with the current code, and each refusing the release the same way. The polygon counts are recorded and never gate, because a zone rename reaches the data as a removal plus an addition
