``FileCoordAccessor.cleanup()`` drops its own whole-file word view of the mapping before it attempts ``mmap.close()``, so the close succeeds instead of being refused by that view and swallowed as a ``BufferError`` - which used to defer the unmapping to whenever the accessor happened to be collected, in the mode that exists so the coordinate data need not be resident. Any view a *caller* holds still refuses the close, which is the case the suppression exists for. No lookup code moved.
