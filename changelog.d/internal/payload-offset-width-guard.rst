``timezonefinder validate-data`` (and the converter, which runs the same checks) now refuses a compiled data directory whose coordinate buffer holds more payload words than a block's payload offset can address. ``PolygonArray`` makes those offsets absolute against the buffer with unsigned arithmetic, so a collection that outgrew the stored width would wrap and point the point-in-polygon kernels at another ring's residuals instead of failing. The two places that record why the width is what it is now name the whole collection's payload as the bound rather than the largest single ring's, which is ~26x smaller and was never the quantity at risk.
