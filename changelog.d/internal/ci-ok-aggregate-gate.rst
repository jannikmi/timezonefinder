the build workflow ends in a single ``ci-ok`` job that aggregates every gate job on a pull request, so branch protection can require one stable context instead of the tox matrix's check names - which carry their matrix values, and therefore rename themselves out of the required list on every matrix edit, un-gating the branch without anything failing. A skipped or cancelled dependency fails it, because a gate that did not run has not passed, and ``tests/test_build_gate.py`` asserts that every non-publishing job in the workflow is listed in its ``needs``, so a new job cannot quietly sit outside the gate
