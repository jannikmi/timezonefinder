The converter's rule for a cell's candidate polygons is tight rather than conservative, and no longer rests on evidence that cannot establish an exclusion. A cell is an axis-aligned rectangle of the stored integer coordinates, so "can this polygon own one of the cell's points" is a planar predicate over two rectangles and a ring, evaluated against the point-in-polygon kernel's own edge convention. It never omits a polygon the kernel can place a cell's point inside, and over-includes only one whose interior enters the cell without reaching any of its integer points - a sliver under ~1.1 cm, costing that cell one bounding-box rejection. ``scripts/hex_utils.py``'s half-turn rotation, polar special cases and three-way overlap tests are gone with the hexagons that needed them, as are the vertex-cell cache and the second copy of every source ring the parse kept for it. ``scripts/audit_shortcut_candidates.py``'s default stream now probes every stored cell's corner integer points, so each grid line is checked from both sides, and ``tests/grid_cells_test.py`` holds the rule to the kernel over randomised polygons rather than leaving it to that once-per-dataset audit.
