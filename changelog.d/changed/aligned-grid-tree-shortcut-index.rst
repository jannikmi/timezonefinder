The shortcut index is now a longitude/latitude-aligned grid tree instead of an H3 hexagon grid: 0.9375° cells, each refining into a 4×4 block of 0.234375° cells where several zones meet. The cell is two integer divisions per level rather than a library call, so it vectorises over a batch, and the cells are exact in the coordinate frame the point-in-polygon kernel reads, so a zone whose polygons only reach across a cell edge is no longer a candidate inside it. Random ``timezone_at()`` lookups measured ~1.5x faster and ``timezone_ids_at()`` batches 5x on uniformly random points and ~25x where a single zone covers the cell, against a 20 % smaller index on disk and half the resident index arrays; ``TimezoneFinderL``'s footprint roughly halves. ``TimezoneFinder``, ``timezone_at()``, ``timezones_at()`` and ``certain_timezone_at()`` answers do not change - 200,000 area-weighted random points, 14,742 points in two overlapping zones, both poles and both antimeridian spellings all answer exactly as before - but ``TimezoneFinderL`` is an approximation *by cell*, so its answers move where a cell does, and it now agrees with the full lookup more often. This is a binary format change: ``DATA_FORMAT_VERSION`` is 4 and the required ``timezonefinder-data`` floor moves with it.
