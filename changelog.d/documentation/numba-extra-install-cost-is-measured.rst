The `acceleration path comparison <https://timezonefinder.readthedocs.io/en/latest/benchmark_results_acceleration_paths.html>`__ now also measures what installing the optional ``numba`` extra costs a process *before* any query - resident memory and time from a cold process to its first answer, in both environments, with the difference stated as the price of the extra - because speed was the only consequence the page priced and it is not the one a container memory limit or a cold-start budget is spent against. The README, `getting started <https://timezonefinder.readthedocs.io/en/latest/0_getting_started.html>`__, the performance page and the architecture page say so where they offer the extra, and the architecture page no longer claims the JIT compiles on first use: the signatures are eager, so a finder's construction pays the compilation.
