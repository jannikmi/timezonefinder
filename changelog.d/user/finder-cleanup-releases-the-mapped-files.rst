``TimezoneFinder.cleanup()`` and the ``with`` block that calls it now actually release the memory-mapped coordinate files. They released nothing: each polygon array was handed to an internal best-effort ``close()`` helper, and neither array has ever had a ``close()`` method, so the resulting ``AttributeError`` was suppressed as an expected close failure and both mappings plus their file handles stayed open until the finder was garbage collected - which is precisely what a context manager exists to make unnecessary. Code that opens finders in a loop under the default ``in_memory=False`` accumulated two open descriptors and one mapping per iteration. The release is now ordered explicitly, so it happens by the time ``cleanup()`` returns rather than at some later collection. **A finder must not be used after ``cleanup()``**: a lookup that reads geometry now raises ``AttributeError`` instead of answering. That rule was previously stated only on the internal accessor and could not bite while the public call released nothing; the `usage documentation <https://timezonefinder.readthedocs.io/en/latest/1_usage.html>`__ now describes both the rule and the context manager. Lookups, answers and construction are unchanged.
