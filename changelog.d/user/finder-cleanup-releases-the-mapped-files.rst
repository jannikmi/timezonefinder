``TimezoneFinder.cleanup()`` and the ``with`` block that calls it now actually release the memory-mapped coordinate files. They released nothing: each polygon array was handed to an internal best-effort ``close()`` helper, and neither array has ever had a ``close()`` method, so the resulting ``AttributeError`` was suppressed as an expected close failure and both mappings plus their file handles stayed open until the finder was garbage collected - which is precisely what a context manager exists to make unnecessary. Code that opens finders in a loop under the default ``in_memory=False`` accumulated two open descriptors and one mapping per iteration. The release is now ordered explicitly, so it happens by the time ``cleanup()`` returns rather than at some later collection. **A finder must not be used after ``cleanup()``**, which has always been the documented contract but was unenforceable while the call did nothing: a lookup that reads geometry now raises ``AttributeError`` instead of answering. Lookups, answers and construction are unchanged.
