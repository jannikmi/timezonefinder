# Documentation markup, links and generated pages

The mechanics that keep `README.md`, `CHANGELOG.rst` and `docs/` building, linking and current. What the prose may say is in the [documentation maintenance rules](documentation-maintenance-rules.md).

- **`README.md` is the PyPI long description** (`readme` in `pyproject.toml`), rendered as GitHub-flavoured Markdown on PyPI and GitHub alike, and nothing else builds it: the docs do not include it, and no hook checks its markup or links — `blacken-docs` formats its Python fences and nothing more. **Write it one line per sentence**, and per clause where a sentence's clauses are edited independently — the rendered page is the same, and a one-word change then diffs as one line rather than reflowing a paragraph. Centring or sizing an image takes an HTML block (`<p align="center">`); PyPI's sanitiser keeps `align`, `width`, `alt`, `src` and `href` and strips `style`, so render it before relying on any other attribute. **`CHANGELOG.rst` must be valid *standalone* RST**: the docs `include` it, but it is also read on GitHub, where a Sphinx role (`:doc:`, `:ref:`) renders as raw text. Link with an absolute `https://timezonefinder.readthedocs.io/…` URL instead. `rstcheck` lints it but does not resolve roles, so an unknown one passes at every report level
- The `rstcheck` hook covers `docs/` too, with `sphinx` installed into its environment so the directives Sphinx owns are recognised, and `[tool.rstcheck]` in `pyproject.toml` naming the three it still cannot see (`autoclass`, `autofunction`, `include`). A bare `rstcheck` run reads the same config, so it agrees with the hook. It catches structural RST — a directive running into the block after it, a malformed table — which is worth knowing because `docs/` used to be excluded and the exclusion was silently load-bearing: those defects reached `master` and only `make docs` complained
- **Every target in `README.md` must be absolute, and an image source is a target too.** A repo-relative `docs/…` path is a real location on GitHub and no location at all on PyPI, which serves the long description without the repository — and `docs/` is excluded from the sdist by the `check-manifest` ignore list, so the file is not even shipped. Point images at `https://raw.githubusercontent.com/jannikmi/timezonefinder/master/…`. Nothing lints this, and a Markdown link whose target does not resolve renders as a link all the same, so verify with `uv run --isolated --no-project --with 'readme-renderer[md]' python -m readme_renderer README.md -o tmp/readme.html` and open it — without the `md` extra the renderer warns and emits the source unrendered. `docs/index.rst` is the opposite case — it sits next to the images, so its paths stay relative
- **`README.md` deep-links into `docs/` by anchor, and Sphinx derives an anchor from the heading text.** Renaming a heading in `docs/` silently breaks every README link to it: the page still loads, just at the top, so nothing 404s and nothing warns — `rstcheck` does not resolve targets and `make docs` does not know `README.md` exists. After renaming a heading in a `docs/` page, grep `README.md` for `<page>.html#`. When adding such a link, read the slug out of the built page (`grep -o 'id="[a-z0-9-]*"' docs/_build/html/<page>.html`) instead of deriving it by hand
- `docs/` pages are Sphinx-built. `docs/index.rst` carries four captioned toctrees — *Using it*, *Design*, *Performance*, *Project* — and a new page belongs in exactly one of them; listed in none it is orphaned and unreachable from the sidebar, listed in two it is a duplicate entry. `make docs` warns on both, and must build without new warnings — but `rstcheck` will not catch a broken cross-reference there
- Generated docs: `docs/benchmark_results_*.rst` (`scripts/render_benchmark_reports.py`), `docs/data_report.rst` (`scripts/reporting.py`), and `docs/tzfpy_agreement.json` plus `docs/tzfpy_agreement_by_distance.svg` (`scripts/measure_tzfpy_agreement.py`). The [core contract](../core-contributor-contract.md)'s rule against editing generated files applies. The last two are one run in machine-readable and rendered form; `--from-json --chart` redraws the committed run without installing `tzfpy` or repeating the measurement
- **A change that moves a measured path regenerates the report pages it moves, in the pull request that moves it** — dispatch `benchmark.yml` with `render_reports=true` and `reports` set to the affected groups (`suite`, `memory`, `acceleration`, `break-even`, `data`; default `all`) on the changed commit, and install its commit-bound artifact as the release workflow specifies; the artifact replaces only the pages it carries. When unsure which groups a change moves, render `all`. On a `release/**` branch the push starts that render on its own; everywhere else the dispatch is still manual. It applies to a footprint as much as to a timing: `benchmark_results_memory.rst` is a committed measurement too, and a change to what an accessor builds at construction moves it. Stale generated measurements are the worst kind of stale — nothing fails, the page still builds and renders, and a figure describing a tree that no longer exists reads exactly like a current one. The artifact's pages print the CI runner CPU; never replace them with a contributor-machine run.
- **`make reports` re-measures everything** — it has `benchmarks`, `latency` and `memory` as prerequisites — so it rewrites every committed figure on all four report pages. To change only the *rendering*, invoke the renderer directly against the stored JSONs; measurement and rendering are decoupled: `uv run python -m scripts.render_benchmark_reports --benchmark-json=tmp/benchmark.json --latency-json=tmp/latency.json --memory-json=tmp/memory.json` (omit `--memory-json` to leave `docs/benchmark_results_memory.rst` untouched; `--latency-json` cannot be omitted, because the per-query distribution is a section of the timezone-finding page rather than a page of its own). Confirm the JSONs are the ones behind the committed reports by re-rendering *before* your change and checking that `git diff docs/benchmark_results_*.rst` is empty. `docs/data_report.rst` is the exception among the four: it needs no measurement at all, so `uv run python -m scripts.reporting` regenerates it from the packaged binaries in seconds — never reach for `make reports` to update it
