# Runtime, geometry, and data checks

Do not re-raise these findings without new evidence.

- **Exception handling:** the broad `except Exception` in `MemoryCoordAccessor`/`FileCoordAccessor.__init__` cleans up partial state and re-raises; `utils.close_resource`'s suppression list is documented at length and includes `BufferError` on purpose; `TimezoneFinder.__del__` uses a two-tier handler that warns on the unexpected case; and `scripts/reporting.py`'s `main` catches `Exception` to print a traceback and return an exit code.

- **Resource lifetime and tool idioms:** `coord_accessors.py`'s bare `open()` (Ruff `SIM115`) deliberately creates a handle that outlives the call and is closed by `cleanup()`; the `profile` name probes in `scripts/hex_utils.py` and `scripts/shortcuts.py` (Ruff `B018`) are the standard `line_profiler` idiom; `scripts/measure_memory.py`'s `subprocess.run` without `check=` (Ruff `PLW1510`) inspects `returncode` and raises with the child's output; and `np_binary_helpers.py`'s six near-identical `get_*_path` helpers preserve six importable, singly declared path names rather than one string-keyed lookup.

- **Workflows and global facade:** `.github/workflows/benchmark.yml`, `benchmark-comment.yml`, `check_data_updates.yml`, and `release_data_update.yml` were read in full and yielded nothing beyond version drift that is now guarded. `timezonefinder/global_functions.py`'s module-level `TF_INSTANCE` and `global` statement (Ruff `PLW0603`) are deliberately documented as not thread-safe, with per-thread instances as the alternative. `scripts/hex_utils.py`'s antimeridian and pole clipping in `get_corrected_hex_boundaries` is covered by `tests/hex_utils_test.py`.

- **Data integrity and package boundaries:** `scripts/data_integrity.py`'s two validators each build their own `PolygonArray`/`HoleArray`, but they are separate entry points with different subjects—cross-file agreement and an upstream-data expectation—and `__del__` releases the accessors either way. `packages/timezonefinder-data/timezonefinder_data/__init__.py` and `scripts/data_releases.py` were read in full and found sound. `timezonefinder/zone_names.py` deliberately lets `read_zone_names` take a default path while requiring one for `write_zone_names`, because defaulting the write side to `DEFAULT_DATA_DIR` could rewrite the installed dataset in `site-packages`.

- **A failed certainty probe does not by itself prove a shortcut omission.** `certain_timezone_at()` tests every candidate but the point-in-polygon kernel has no promised side for a point exactly on a stored boundary. At the exact South Pole, and at border offsets smaller than the package's coordinate grid, an exhaustive scan can find no containing packaged polygon either. Diagnose an index omission only when exhaustive point-in-polygon testing finds a containing polygon absent from the cell's candidates; `None` alone establishes only that no candidate contained the quantized point.
