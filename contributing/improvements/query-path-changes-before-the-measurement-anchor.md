# Query-path changes before the measurement anchor

Changes to the query path that landed before the anchor of the [query performance measurement baseline](query-performance-measurement-baseline.md), so its denominators never included them. They bear on freshness only through the rules they state, which is why they are kept; the changes since the anchor are classified in the [query-path change-classification log](query-path-change-classification-log.md).

- **2026-08-23, the negative-id guard on the public id-taking methods: inert.** It adds a check to four public methods and moves the internal callers onto private accessors with identical bodies, so the query path executes the same number of calls over the same statements. Nothing in the `zone name` block or the ladder above it changed.
- **2026-08-23/24, the batch lookups: not inert on the ambiguous stratum, and measured.** The candidate loop became shared with the batch path, so an ambiguous `timezone_at` executes **exactly one more Python method call**. That count is the durable fact; the time it costs read as order 1 % of an ambiguous query across two paired runs whose estimators straddled, and must not be quoted to a second decimal. Kept deliberately: the alternative was a second copy of the stop-index and untested-last-zone logic, which is the drift this file exists to prevent, and `test_batch_and_scalar_agree_over_every_committed_point` is what makes the remaining duplication safe. The unique stratum, ~89 % of a random workload, executes not one changed statement.
- **2026-08-24, per-cell preparation shared across a batch: inert for the scalar path, and a real batch win.** Splitting a cell's preparation out of the loop that works it, and memoising it by shortcut entry inside a batch. Scalar `timezone_at` measured neutral with the estimators disagreeing in both backends, which is what neutral looks like; the batch path's ambiguous stratum gained **-3.8 % (clang) / -6.3 % (numba)**, both estimators agreeing. **The generalisable half:** what a batch can amortise is whatever is a property of the *cell* rather than of the point, so that is the line to split a per-point loop along. The prices it quoted are superseded - the 2026-09-06 entry deleted the zone id gather, which was a third of what that tuple held.
- **2026-08-24, reading a batch's arrays once per stage rather than once per point.** `int(entries[i])` and the two `float(...[i])` in the ambiguous resolvers are numpy scalar extractions: **242 ns per point** for the three against **103 ns** for the same values taken through `tolist()` up front. That is loop overhead, paid whether or not the point's cell was already prepared. Measured over 2,000 ambiguous fixture points, three paired rounds, `in_memory=False`, min / median ns per point: `TimezoneFinderL` **878 -> 755 (-14.1 %) / 936 -> 809 (-13.5 %)** — it also stopped using a dict, its answer being a pure function of the entry — and `TimezoneFinder` **10,021 -> 9,937 (-0.8 %) / 10,599 -> 10,554 (-0.4 %)**, where ~10 µs of geometry per point is what makes the same nanoseconds invisible. Both estimators agree in sign in both classes. **The general rule, and the reason this is recorded rather than just fixed:** a numpy scalar extraction inside a Python loop costs more than most of the loop bodies in this repository, so hoist the whole column out of the loop wherever a batch is walked point by point.
- **2026-08-25, the shortcut compiler's hole-side overlap fix and its antimeridian frame: both inert for timings.** Each changes `scripts/`, not `timezonefinder/`, so not one statement on the query path moved; what they move is the packaged `shortcuts.bin`, for **21 of 288,122 cells** (17 of which stopped resolving to a single zone) and **3 of 288,122** (none of which changed stratum, all three already holding a candidate list). The committed benchmark fixtures were checked against those cells rather than assumed clear: **no `unique_shortcut` or `random` point falls in one**, so no fixture point changed stratum and the fixtures did not need regenerating; 7 of 10,000 `on_land` and 2 of 5,000 `ambiguous_shortcut` points now test one additional candidate, a bounding-box rejection on ≤0.03 % of a fixture. The ladder, the denominators and every share above stand, and `docs/benchmark_results_*.rst` were deliberately **not** re-measured: re-running them would replace every committed figure with a fresh machine's for a change nothing can resolve. `docs/data_report.rst` was regenerated, since it counts the index rather than timing it.
