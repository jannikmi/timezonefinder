# GH-332 — reduced timezone dataset as a second distribution


## Related memory

- [Data distribution, packaging, and release decisions](../../decisions/data-distribution-packaging-and-release-decisions.md)
- [Improvement sequencing and preconditions](../../improvement-sequencing-and-preconditions.md)
- **Tracks:** issue #332, which carries the reframing and the costs.
- **Why it is ranked here:** 63 zones instead of 444 on the 2026c release — counted from the vendored table rather than remembered; "~90" was in the entry and in `docs/data_format.rst` until it was checked — and the distribution split turned it from a build-time switch into a packaging decision.
- **Decided, 2026-08-21 — no hand-maintained mapping.** Shipping with one was declined: until the official table exists it is the same liability the zone-precedence engine was rejected for. That decision stands and is unaffected by what follows; only its precondition changed.
- **Unparked, 2026-09-02; unblocked, 2026-09-03.** The official table exists and is now in the tree: `tests/fixtures/reduced_zones/mapping.json` holds the release asset verbatim, `source.txt` beside it records the release and digest it was verified against, `update_data.sh` re-takes it with every data update, and `tests/auxiliaries.py:convert_to_reduced_timezone` converts a location expectation through it whenever the packaged data is the reduced variant. So the mapping half is done and this entry no longer waits on anything.
- **Status:** parked — resume only on evidenced user demand for an installable reduced dataset. Nothing technical is in front of it and nothing sequences behind it; what is missing is a user. Note what the vendored mapping does *not* cover: it converts a zone name, so the expectations reached through `single_location_test` hold on either dataset, while the ocean cases in `TEST_LOCATIONS_AT_LAND` do not — under the reduced data an ocean zone merges into a *land* representative, which changes what `timezone_at_land` returns rather than what it is called. That is this item's work, not a gap in the mapping. The costs on the issue are unchanged; they were never the reason for the park.
- **Decided, 2026-09-05 by the maintainer — publish nothing yet; park on demand.** The reduced `timezones-now` dataset does not become a published artifact. The converter route (`update_data.sh --dataset=same-since-now`) stays the answer and is already documented — `docs/data_format.rst` "Alternative Dataset Options" states the switch, the caveats and the vendored mapping, and `README.rst` links to it — so this costs nothing and leaves no documentation task behind. The item is **parked rather than closed**, because the objection is missing demand, not a dead end: the shape below is ready to build the moment somebody asks for it. **Resume on:** a user asking on issue #332 for an installable reduced dataset. *Refused, with the reasoning kept:* **(a)** a second distribution, `timezonefinder-data-reduced`, versioned on the same `<format>.<year>.<letter>` axis and installed instead of `timezonefinder-data` — the shape the 2026-08-06 comment on issue #332 proposed. It buys a user a 63-zone dataset with one dependency swap, at the cost of a second release axis to keep in step with the format version, a second ~52 MB-per-release PyPI project, and every zone name in `README.rst` and `docs/1_usage.rst` becoming dataset-dependent (the failure that already put `'Europe/Paris'` on eleven full-dataset examples). Refused on demand, not on merit — it is the shape to build if demand arrives. **(c)** publishing it as an extra file set inside the existing `timezonefinder-data` wheel, selected at runtime: one release axis and one project, but it enlarges the download for every user in order to serve the users who wanted it *smaller*, which inverts the point. Refused on merit, and not to be re-proposed — the generalisable half is that a proposal which consolidates release axes at the cost of the property the item exists to deliver has not simplified anything. It is recorded here rather than in the [distribution decisions](../../decisions/data-distribution-packaging-and-release-decisions.md) because this decision constrains no other item, and because a parked entry is not deleted the way a shipped one is, so this file keeps it. *Why now and not later:* the item has been open since 2024 with no user in it asking to install a package, and reversal is the expensive direction — a PyPI project name is claimed permanently and its releases cannot be deleted, with PYPI-1 already recording this project holding 11.37 GB. Parking costs nothing and (a) later costs only the work itself. *Unpriced, and still is:* how many of the 63-zone dataset's would-be users can run the converter at all, and whether a second data axis stays in step across a `DATA_FORMAT_VERSION` bump without a second ordered release rehearsal. Neither can be priced without the demand this now waits on.
- **Last touched:** 2026-09-05 — decided and parked on demand; the call for users to voice demand is on issue #332.
