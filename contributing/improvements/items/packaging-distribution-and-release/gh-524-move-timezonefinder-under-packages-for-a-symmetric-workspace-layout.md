# GH-524 — move `timezonefinder` under `packages/` for a symmetric workspace layout


## Related memory

- [Data distribution, packaging, and release decisions](../../decisions/data-distribution-packaging-and-release-decisions.md)
- **Tracks:** issue #524 — the asymmetry the distribution split deliberately left behind, and the machinery a move has to rewire.
- **Premise re-verified 2026-09-05, unchanged.** `timezonefinder/` is still at the repository root, `packages/` still holds `timezonefinder-data` alone, and the root `pyproject.toml` is still both the workspace root (`[tool.uv.workspace] members = ["packages/*"]`) and the code package's own manifest.
- **What a move has to rewire, all of it root-relative today:** `setup.py`'s `cffi_modules=["timezonefinder/build.py:ffibuilder"]`; the seven dotted names in `[tool.setuptools] packages`; `MANIFEST.in`, which both `recursive-include timezonefinder` and `prune packages` — so a naive move deletes the code from the sdist; the `check-manifest` hook's root-relative ignore list in `.pre-commit-config.yaml`, which also ignores `packages/*`; `build.yml`'s `make-wheels` job, which runs `pypa/cibuildwheel` against the repository root with no `package-dir`; `scripts/configs.py`, which derives `PROJECT_ROOT` from its own location; `tox.ini`; and `docs/conf.py`'s `sys.path` insertions.
- **Its stated trigger has not fired.** The move's real justification on the issue is that a *third* distribution stops being a special case; absent one it is, in the issue's own words, close to cosmetic, and it spends risk on the release path to buy tidiness. GH-332 is the only candidate third distribution and is itself waiting on a decision about whether it is published at all.
- **The `tests/` question is the contributor's, and is answered: one suite, at the root.** The issue raised splitting `tests/` per package as an open question. It is test structure, so it does not belong to the maintainer, and the answer is not to split: `tests/auxiliaries.py` imports from `scripts/`, `scripts/`, `benchmarks/` and `docs/` serve every package and stay at the root either way, and a split would have to resolve that dependency first for no gain the move itself needs. Whoever implements the move keeps the single suite; only the distribution directories move.
- **Status:** needs a maintainer decision on whether the move happens now, waits for a third distribution, or is refused.
- **Decision needed:** does `timezonefinder` move under `packages/`, and when? *Consequences:* the move is a wide, low-insight diff across exactly the machinery whose failure mode is "no release goes out", and it lands on the sdist contents, the wheel build root and the `check-manifest` gate at once; against that it buys a layout in which neither distribution is privileged and a third one is mechanical to add. Timing is the whole question, because the work is the same whenever it is taken and the risk is only worth paying when something needs the symmetry. *Options:* **(a)** take it now as its own pull request — the layout stops reading as an accident, and the rewiring is verified while no format or data release is in flight; the cost is that the sdist, wheel and manifest gates all change in one diff for a benefit no current work is waiting on, and every open branch that touches `timezonefinder/` rebases across a rename. **(b)** park it on its own trigger: implement it in the pull request that adds a third distribution, so the risk is paid once, by the change that needs it, and the symmetric layout is verified by adding a real member to it rather than by inspection. Costs nothing now; leaves the asymmetry standing indefinitely if no third distribution is ever published. **(c)** refuse it and record the current shape as intended — the root manifest doubling as the workspace root is legal, `uv` supports it, and a package that never gains a third distribution never pays for the asymmetry. Ends the item and stops it being re-proposed on tidiness. *Recommendation:* (b), with (c) as the honest fallback: GH-332 is the only route to a third distribution on record, and if it is answered "publish nothing" then (b) is a park with no foreseeable trigger and the item should be closed under (c) rather than left in the ranking. *Reversibility:* (b) and (c) cost nothing to reverse — the work is unchanged whenever it is taken. (a) is the expensive direction: reverting means a second wide diff across the same release machinery, plus a second rebase for every branch that moved. *Unpriced:* whether the release path survives the move without a tag-ref rehearsal. The publish guard added in PR #529 runs only on tag refs, so no pull request exercises it, and the first run that can report a broken wheel build root is the one already publishing.
- **Last touched:** 2026-09-05 — briefed for a decision after re-verification found the premise intact and the trigger unfired; the `tests/` question answered as the contributor's.
