# GH-524 — move `timezonefinder` under `packages/` for a symmetric workspace layout


## Related memory

- [Data distribution, packaging, and release decisions](../../decisions/data-distribution-packaging-and-release-decisions.md)
- **Tracks:** issue #524 — the asymmetry the distribution split deliberately left behind, and the machinery a move has to rewire.
- **Refused 2026-09-06 by the maintainer: the current layout is the intended one, and the move does not happen.** The root `pyproject.toml` doubling as both the workspace root and the code package's manifest is legal, `uv` supports it, and a package that never gains a third distribution never pays for the asymmetry. Recorded in the [packaging decisions](../../decisions/data-distribution-packaging-and-release-decisions.md) so the tidiness argument does not come back as a fresh proposal. Reopen only on evidenced demand for a third distribution, which today means GH-332 being reopened.
- **Why parking was refused too.** The item's own recommendation was to park the move on the pull request that adds a third distribution, with refusal as the honest fallback — and that fallback condition had fired before this decision: GH-332 is the only route to a third distribution on record and was answered "publish nothing" on 2026-09-05. A park whose trigger is a question already answered "no" is a row every later re-verification pays to re-read and no pass can ever take.
- **Why taking it now was refused.** The move is a wide, low-insight diff across exactly the machinery whose failure mode is "no release goes out", and it lands on the sdist contents, the wheel build root and the `check-manifest` gate at once — for a benefit no current work is waiting on, plus a rebase across a rename for every open branch touching `timezonefinder/`.
- **Premise re-verified 2026-09-06 at c27b452, unchanged.** `timezonefinder/` is still at the repository root, `packages/` still holds `timezonefinder-data` alone, and the root `pyproject.toml` is still both the workspace root (`[tool.uv.workspace] members = ["packages/*"]`) and the code package's own manifest.
- **What a move would have had to rewire, all of it root-relative, kept so a future third distribution does not rediscover it:** `setup.py`'s `cffi_modules=["timezonefinder/build.py:ffibuilder"]`; the seven dotted names in `[tool.setuptools] packages`; `MANIFEST.in`, which both `recursive-include timezonefinder` and `prune packages` — so a naive move deletes the code from the sdist; the `check-manifest` hook's root-relative ignore list in `.pre-commit-config.yaml`, which also ignores `packages/*`; `build.yml`'s `make-wheels` job, which runs `pypa/cibuildwheel` against the repository root with no `package-dir`; `scripts/configs.py`, which derives `PROJECT_ROOT` from its own location; `tox.ini`; and `docs/conf.py`'s `sys.path` insertions.
- **The unpriced risk that survives the refusal, and would have to be paid by whoever ever takes the move.** The publish guard added in PR #529 runs only on tag refs, so no pull request exercises it, and the first run that can report a broken wheel build root is the one already publishing. A move therefore needs a tag-ref rehearsal, not just a green pull request.
- **The `tests/` question is the contributor's, and is answered: one suite, at the root.** The issue raised splitting `tests/` per package as an open question. It is test structure, so it does not belong to the maintainer, and the answer is not to split: `tests/auxiliaries.py` imports from `scripts/`, `scripts/`, `benchmarks/` and `docs/` serve every package and stay at the root either way, and a split would have to resolve that dependency first for no gain the move itself needs.
- **Status:** rejected — the asymmetric layout is intended; kept as the argument against re-proposing the move on tidiness.
- **Last touched:** 2026-09-06 — refused by the maintainer after re-verification found the premise intact and the third-distribution trigger permanently unfired.
