# BENCH-4 — nothing dispatches the benchmark report render, so a release must remember to

- **What is missing.** `benchmark.yml`'s `render-reports` job runs only on `workflow_dispatch` with `render_reports=true`. Nothing starts it: the workflow's `pull_request` trigger is path-filtered to `timezonefinder/**`, `packages/timezonefinder-data/**`, `benchmarks/**`, `scripts/**`, the build inputs, `Makefile` and the workflow file, and a release pull request touches none of them. So the pages the release commits exist only if a person remembered to press the button first, against the right commit.
- **Only the trigger is open; who commits is settled.** The 2026-09-02 decision fixes that CI must never commit the pages — the `pull_request` half of `benchmark.yml` executes untrusted head code and deliberately holds no write permissions and no secrets, so a `contents: write` token cannot live there. That constrains this item rather than blocking it: the wanted change moves the *dispatch* off the human and leaves the *commit* with the release, exactly as it is now.
- **The failure it removes.** A release refreshing stale pages must dispatch first and then pick the run whose head SHA equals the release SHA. Skip it, or take the newest run on branch name alone, and `scripts/benchmark_report_artifact.install_artifact` raises on the stamp mismatch. That is the good half — the release stops rather than committing another tree's numbers — but it stops late, at release time, on a step whose prerequisite ran nowhere.
- **The routes, none of them costed yet.** Dispatch from the release path itself, which needs `actions: write` somewhere and is therefore a permissions question before it is a code one; or add the release pull request's own paths to the `pull_request` filter, which spends a 60-minute `make reports` budget on every push to that branch rather than once; or trigger on the version-bump commit. Cost them against how often a release actually refreshes the pages — the runbook already tells the reader to check staleness and skip the step when nothing since the newest tag touched `timezonefinder/`, `packages/`, `DATA_VERSION` or `benchmarks/`.
- **The precedent says manual is defensible, not that it is finished.** `compile_data.yml` is `workflow_dispatch:`-only too, and the release runbook already carries the same "confirm the run succeeded and its artifact has not expired, re-dispatch and record the new id" step for `DATA_BUILD_RUN`. Whatever is decided here is worth reading against that one: two manual dispatches on one release path is the case for automating, and a single consistent ritual is the case against.
- **Status:** open — the constraint is recorded and the routes are named; what is missing is the cost of each against how often the step actually runs.
- **Last touched:** 2026-09-04 — raised when BENCH-2/BENCH-3 shipped the dispatchable render job.
