# PERF-7 — a single-block ring pays for a block index it can never skip with


## Related memory

- [Query-path and shortcut-index decisions](../../decisions/query-performance-and-shortcut-index-decisions.md)
- [Query performance measurement baseline](../../query-performance-measurement-baseline.md)
- **No issue tracks this; found 2026-08-30 while measuring the latitude block index that created it.**
- **What it is.** 29.7 % of boundary polygons fit in a single block, and for those the filter is pure overhead: `pip_with_bbox_check` has already rejected every point outside the ring's bounding box, and a single block's latitude range is that bounding box's — so by the time the kernel runs, the one block always survives and the scan is the full ring either way. What is paid for that is the block-range comparison itself, and nothing else any more: the slice and the third `ffi.from_buffer` that made up most of this item's original price were both removed when the packed payload gave the kernels the collection's arrays and a block offset.
- **What it costs, re-measured 2026-08-31 under polygon layout 3, and it is now small.** `prototypes/query_stage_profile.py` prices one point-in-polygon call on the `small` stratum (112 vertices) at **537 ns clang / 818 ns numba**, against `medium` 567 / 891 and `large` 745 / 1,619. The gap between `small` and `medium` is what a single-block ring cannot use, and it is now tens of nanoseconds rather than the ~400 ns this item was created for — the packed payload removed the per-call slice and marshalling that were most of it. Recorded rather than deleted because the *second* overhead below is unaffected and is now the larger half.
- **The shape of the fix.** `PolygonArray.pip` resolves `(start, stop)` from `block_offsets` first and calls the unblocked kernel when `stop - start == 1`. `HoleArray` resolves ids through `poly_ref`, so the pair has to be overridden together exactly as `coords_of` / `block_ranges_of` already are — that is the trap, and the one this item must not re-discover.
- **A second, larger overhead sits in the same place, found 2026-08-30 by asking whether the two kernels are redundant.** The blocked kernel costs **~48 % more per scanned edge than the bare one on clang** and ~96 % more on numba, measured by giving it a single all-encompassing block so the filter removes nothing and only the loop differs. Most of what remains is the wrap test: the blocked loop computes `j = i + 1; if (j == nr_coords) j = 0` on *every* edge, where the bare loop carries the previous index and pays nothing. Only the last block's last edge can wrap, so the inner loop can run over `[start, stop - 1)` unconditionally and handle that one edge outside it. (The latitude-comparison carry, which was the other half of the gap, was restored when this was found — inside a block consecutive edges still share a vertex, so only a block's first vertex needs its comparison made from scratch.)
  - Now the larger of the two halves, since the per-call overhead above has largely gone: the kernel *is* the point-in-polygon call under layout 3 (537–745 ns clang), so ~48 % of its per-edge cost is a real share of it rather than a share of a kernel buried under marshalling. Re-measure before taking it — the figure was taken on the layout 2 kernel, and the packed kernel's per-edge work is different.
- **Why it was not taken with the index itself.** ~200 ns on an average point-in-polygon call was ~3 % of an ambiguous query and well under the 3–9 % noise floor, so no benchmark in this repository could demonstrate it. The [register rules](../../improvement-register-rules.md) rank such a change on simplicity instead, and a branch on the hot path is not simpler than no branch. It needs the count argument above to be worth anything, which is why the count is recorded here rather than the timing.
- **Check before taking it** that the bounding-box argument still holds: it depends on `pip` only ever being reached through `pip_with_bbox_check`. `certain_timezone_at` and the hole loop both go through it today; a future caller that does not would make the skip real for single-block rings and this item wrong.
- **Status:** open — free, small, and ranked low because it is below what any benchmark here can resolve.
- **Last touched:** 2026-08-31 — re-measured under polygon layout 3, which removed most of the per-call half and left the per-edge half as the item's remaining substance. Created 2026-08-30 from the profiler's `small` stratum row when the latitude block index landed.
