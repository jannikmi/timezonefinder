# TOOL-1 — six ruff rule families are enforced nowhere, and the version bump waits on two

- **Location:** `pyproject.toml`, `[tool.ruff.lint]` — `ignore = ["B023", "B905"]`; `.pre-commit-config.yaml`, the `ruff-pre-commit` rev; `pyproject.toml`, the `dev` group's `ruff<0.16`.
- **What is already done.** `select` is explicit and holds ruff's defaults plus the whole `flake8-bugbear` family and `RUF013` — so `B904` and `RUF013`, which are clean, are now held clean by `make hook` and by CI instead of by an ad-hoc run nobody repeats. What `prototypes/` is exempt from is stated once, in `[tool.ruff.lint] exclude`, and `tests/test_lint_configuration.py` asserts that the exemption excludes and that each default rule still fires.
- **Defect:** six families this register has surfaced findings in are still enforced nowhere — **75 sites, all measured on ruff 0.15.22 on 2026-09-05** — and the ruff version is held at 0.15.x because raising it needs the same work. Two are selected-but-ignored, four are not selected at all:

  | family | sites | state |
  |---|---:|---|
  | `B905` | 27 (18 files) | ignored in `[tool.ruff.lint]` |
  | `B023` | 24 (2 files) | ignored in `[tool.ruff.lint]` |
  | `PLR09xx` | 18 (`PLR0913` 10, `PLR0915` 5, `PLR0912` 2, `PLR0911` 1) | not selected |

  The four unselected families are *not* covered by what shipped — `B` and `RUF013` do not contain them — and each needs its own judgement about whether it is worth adopting at all. `PLR09xx` in particular prices complexity limits, which is a threshold argument rather than a defect list.
- **`B023` — 24 sites, nearly all in `timezonefinder/_data_integrity.py`.** The rule flags a function defined inside a loop that closes over the loop variable, which is wrong exactly when the closure outlives the iteration. Every site needs reading: the validators in `_data_integrity.py` look like they are called within the iteration that builds them, which would make all of them false positives, but that has to be established rather than assumed — the failure mode if it is wrong is a validator silently checking the last collection instead of its own. `tests/test_border_sampling.py` has the remaining two. **Detection widened at 0.16 rather than the code changing:** the 2026-08-14 reading of this family as "clean repo-wide" was taken on 0.15 and is no longer true even there, measured 2026-09-05 at 0.15.22.
- **`B905` — 27 sites across 18 files outside `prototypes/`**, spread over `scripts/`, `tests/`, `benchmarks/`, `examples/` and four library modules. Each needs the judgement of whether the two iterables can differ in length. **One earlier conclusion here was wrong. It is kept rather than deleted, because the shape recurs and the next pass would otherwise re-raise it at full price.** The worry was that the FlatBuffers shortcut reader's `zip(poly_id_hex_ids, poly_id_lengths)` — then the only site on the library's own load path — could truncate silently, dropping shortcut entries the lookup would read back as "no candidate polygons", so those coordinates would answer `None` rather than raise. It could not: the two lists were local accumulators appended in the same iteration of the same loop a few lines above the `zip`, with no file read between them, so `strict=True` would have asserted what the control flow already guaranteed. That reader has since been replaced by the slot-addressed shortcut index, which pairs nothing, so the site is gone either way. **The lesson that survives it: a `zip` over two accumulators built in one loop is not a truncation risk, whatever the load path.**
- **The ruff version bump is the same pass.** Measured 2026-09-02: on 0.16.5 the widened default set rewrites ~145 sites across 92 files and leaves **~97 findings** needing judgement rather than a fixer — `B023` (24), `EXE001`/`EXE002` (23), `ISC004` (13), `F841` (10), `DTZ001` (7), `BLE001` (7). The hold is what keeps `make hook` green and it is recorded in the [dependency decisions](../../decisions/benchmarking-tooling-and-dependency-decisions.md). Raising it means raising the pre-commit rev and the `dev` group's `ruff<0.16` together, since they are bound so a bare `uv run ruff` cannot disagree with the hook. Clearing `B023` first removes a quarter of that wall, which is why the two halves are one item.
- **Whatever is enabled next, pick deliberately rather than taking a whole family.** `TRY003` / `EM101` / `EM102` fire in the hundreds across `scripts/` and are not worth adopting. `B` was taken whole only because two named exceptions covered it; a family needing six is not the same trade.
- **Status:** open.
- **Last touched:** 2026-09-05 — `B` and `RUF013` were enabled and the item rewritten around what is still unenforced. **The 2026-08-14 reading that `B023`, `B905`, `A001`, `A002` and `PLW2901` were "clean repo-wide" is stale for all five**, re-measured on the same 0.15 line (0.15.22) that produced it: the entry concluded from it that those families "could be enabled on their own", which would have cost a pass to discover otherwise. The counts in the table above are the ones to plan against, and no test regenerates them — re-measure before trusting them.
