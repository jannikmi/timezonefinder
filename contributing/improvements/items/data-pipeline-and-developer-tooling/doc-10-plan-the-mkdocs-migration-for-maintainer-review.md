# DOC-10 — plan the MkDocs migration, and put the plan to the maintainer before any conversion

- **Location:** produces a plan, not a conversion. The plan belongs on a GitHub issue, which is where [the register rules](../../improvement-register-rules.md) put an item's detail — design tables, measurements and implementation notes — and this entry then names it. Nothing under `docs/` is touched by this item.
- **Why the migration is not taken directly.** [DOC-9](doc-9-migrate-the-documentation-from-sphinx-to-mkdocs.md) is big-bang: MkDocs cannot read reStructuredText, so 5,332 lines convert in one pull request with no half-way state to retreat to. A review of that diff cannot answer "is anything missing", because the whole file is new on both sides of every hunk. **The maintainer required on 2026-09-06 that the plan be reviewed before implementation**, which is what this item exists to produce; the requirement is recorded in the [documentation source format decisions](../../decisions/documentation-source-format-decisions.md).
- **The plan must define lossless, because the word decides what the migration is allowed to change.** State the contract as what is preserved and what is deliberately not, and give each half a check that can be run rather than argued.
- **Preserved — every one of these needs a named verification in the plan:** the visible text of every page; every table row and cell; every code block verbatim; every admonition, image and link target; every published URL; every heading anchor reachable from outside the page; the documented API surface. **Deliberately not preserved:** PDF and ePub, given up with the generator decision; the Read the Docs theme's appearance; and the reStructuredText sources themselves, which git retains.
- **The strongest available check is a text diff of the two built trees, and the plan should be built around it.** `make docs` produces Sphinx HTML today. Build it before converting, extract normalised visible text per page, do the same for the MkDocs build, and diff. Every difference must be explainable as theme chrome or navigation, and anything else is a dropped paragraph. This is the only check that can see an omission, as opposed to a malformation — and an omission is the failure mode a wholesale rewrite actually has.
- **Two URL hazards are already found and must be settled in the plan rather than discovered during it.** MkDocs defaults to `use_directory_urls: true`, serving `data_format/` where Sphinx serves `data_format.html` — which breaks the eight `readthedocs.io/en/latest/<page>.html` links in `README.rst` and every external inbound link. **`use_directory_urls: false` reproduces the current URL set exactly** and is the cheaper answer; `mkdocs-redirects` is the alternative if directory URLs are wanted for their own sake. Separately, `README.rst` deep-links three headings **by anchor** — `data_format.html#alternative-dataset-options`, `architecture.html#how-it-ships`, `architecture.html#tests-that-protect-guarantees-not-behaviour` — and Sphinx and python-markdown derive a slug from heading text by different rules. Enumerate every inbound anchor, docs-internal `:ref:` included, and assert each one resolves in the built MkDocs HTML.
- **The generated pages need a value check, not a text check.** The four benchmark pages and the data report are re-emitted by rewritten renderers, so their markup legitimately differs everywhere. Compare the *cell values* parsed out of the old and new pages, rendered from the same stored JSONs; any changed number is an emitter bug, and nothing else can catch one.
- **The API page needs a symbol check.** `mkdocstrings` renders from a different template than autodoc, so its output is not textually comparable. Assert instead that all 12 functions and 2 classes still appear, each with its parameters, return description and docstring prose. **Prove this page first, as a spike, before the plan is finalised**: the package's docstrings are Sphinx-style — 310 `:param:`/`:return:` field lines — so it rests on `griffe`'s `sphinx` parser, the least-travelled of the three it offers. If that disappoints, the plan says so and prices converting the docstrings to Google style as a separate item, rather than the migration discovering it halfway.
- **The plan must also carry:** the construct-by-construct mapping table (42 `list-table`, 36 `code-block`, 28 `note`, 21 `image`, 4 `toctree` with their captions, 98 `:doc:`/`:ref:`, 18 `:sup:`, the two `include`s of `docs/badges.rst`); the `mkdocs.yml` navigation reproducing the four captioned sections `docs/index.rst` declares; what happens to the `rstcheck` hook and `[tool.rstcheck]`; the commit split that makes the single pull request readable; and the rollback, which is that nothing is deleted until the built output has been compared.
- **There are no doctests anywhere in this repository**, so the code snippets are checked by nothing today. The conversion preserves them verbatim; the plan should not assume a test will catch a mangled one.
- **This item ends in a maintainer decision, and that is its deliverable.** Approving the plan unblocks DOC-9. A plan that finds the losslessness contract unaffordable is an equally good outcome and reopens the generator choice, whose refused options are kept for exactly that.
- **Changelog sentence it stands under:** none. It produces a plan and changes no shipped file.
- **Status:** open.
- **Last touched:** 2026-09-06 — filed when the maintainer required a reviewed plan before the migration.
