# DOC-8 — move `CHANGELOG.rst` and the `changelog.d/` fragments to Markdown

- **Location:** `CHANGELOG.rst`, `changelog.d/*/*.rst` (22 fragments today); `scripts/changelog_fragments.py`, `tests/test_changelog_fragments.py`, `docs/6_changelog.rst`, `MANIFEST.in`, `.pre-commit-config.yaml` (the `check-manifest` ignore list names `CHANGELOG.rst` literally).
- **Defect:** 924 lines of headings and bullets, which is the part of reStructuredText that Markdown does strictly better, in a file that grows by a section on every release and by a fragment on nearly every change. It uses no directive and no role. The [documentation source format decisions](../../decisions/documentation-source-format-decisions.md) record why the same move is refused for `docs/`.
- **Unlike [DOC-7](doc-7-move-the-readme-to-markdown-with-semantic-line-breaks.md), this is not also a reflow.** [DOC-5](doc-5-convert-the-remaining-prose-pages-to-semantic-line-breaks.md) already excludes the changelog: the unreleased section and every release back to 8.2.5 are one line per bullet, and the wrapped historical tail below that is deliberately left alone. **Both halves of that stay true here** — convert the tail's markup and leave its line breaks exactly as they are. A converter run over the file would reflow the tail, which is why this is a hand edit.
- **The code coupling is narrow, which is what makes this affordable.** `scripts/changelog_fragments.py` binds the format in three places: `CHANGELOG_PATH`, `FRAGMENT_SUFFIX = ".rst"`, and `_section_bounds`, which locates the unreleased section by requiring a row of `-` under `X.X.X (unreleased)` and becomes a `##` heading match. `INTERNAL_MARKER = "Internal:"` is format-neutral and does not move. `tests/test_changelog_fragments.py` builds reStructuredText-shaped fixtures and has to move with it — that test is the reason this is safe to do at all, since it is what proves no bullet is lost or reordered.
- **`docs/6_changelog.rst` stops being a complication once [DOC-9](doc-9-migrate-the-documentation-from-sphinx-to-mkdocs.md) lands, and is one until then.** The page is a single `.. include:: ../CHANGELOG.rst`, and a reStructuredText `include` parses its target as reStructuredText whatever the extension, so it cannot include Markdown. **Taken after DOC-9 there is nothing to solve** — MkDocs includes Markdown into Markdown. Taken before it, two routes: add `myst-parser` to `docs/requirements_docs.txt` and make that one stub page a `.md` carrying `` ```{include} ``, which is cheap, reversible and thrown away by DOC-9; or drop the include and link to the changelog on GitHub, losing it from the built docs and from the PDF and ePub that `readthedocs.yml` still builds until DOC-9 removes them. Prefer the first if this lands first, and prefer landing it after DOC-9 if the order is free.
- **The published artifact's URL changes.** `CHANGELOG.rst` is what `README` links to and what the release workflow assembles into; GitHub does not redirect a renamed path, so any external bookmark breaks. Judged acceptable — the file is read through the docs page and the GitHub releases view far more than by direct path — but it is the one irreversible-ish edge, and the README link has to move with it.
- **Also update:** `MANIFEST.in`, the `check-manifest` ignore list in `.pre-commit-config.yaml`, `changelog.d/README.md`, `update_data.sh`'s comment, and the changelog file name where the contributor memory states it — `contributing/development/changelog-and-release-note-policy.md`, `contributing/development/documentation-maintenance-rules.md`, `contributing/workflows/prepare-and-publish-code-release.md`. `tests/test_package_contents.py` matches `CHANGELOG*` and needs no change; `tests/test_release_workflows.py` names the file in an assertion message only.
- **Take it when no release is in flight.** The rename touches the file a release branch is editing and the script that assembles it, so landing it against an open release branch is a conflict in the one file whose correctness the release depends on.
- **Changelog sentence it stands under:** the changelog and its unreleased fragments are written in Markdown. Development-only, so `Internal:` — but it is also the last entry the old file will carry.
- **Status:** open.
- **Last touched:** 2026-09-06 — the docs-page complication re-priced against DOC-9. Filed 2026-09-05 with the format decision.
