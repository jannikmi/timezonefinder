# DOC-7 — move `README.rst` to `README.md`, converting its line breaks in the same pass

- **Location:** `README.rst`; `pyproject.toml` (`readme`), `MANIFEST.in` (`include README.rst`), `.pre-commit-config.yaml` (the `rstcheck` hook's coverage), `contributing/development/documentation-maintenance-rules.md`.
- **Defect:** the file every reader meets first — on GitHub and as the PyPI long description — is written in a format the maintainer does not want to write, and it buys nothing here. The README is 171 lines of prose, a badge block and code blocks; it uses none of the directives or roles that make reStructuredText worth its cost on the `docs/` pages, and a Sphinx role is in fact *forbidden* in it, because it renders in the docs build and breaks the PyPI page. The [documentation source format decisions](../../decisions/documentation-source-format-decisions.md) record why the same move is refused for `docs/`.
- **This is the combination of two items, and that is the point.** `README.rst` was one of the eight files in [DOC-5](doc-5-convert-the-remaining-prose-pages-to-semantic-line-breaks.md) with 15 hard-wrapped continuation lines. A format migration rewrites the file wholesale, so reflowing it in the same pass is free, while doing the two separately means reviewing this file's diff twice and re-reading its rendered output twice. DOC-5 has been narrowed to the seven remaining pages accordingly.
- **Fix:** convert the markup by hand, one line per sentence, and per clause where a sentence's clauses are edited independently. **Do not run a converter over it** — `pandoc` reflows and re-wraps prose, which is the state this pass exists to leave behind, and it rewrites link and image targets that the rules below constrain.
- **Three README-specific rules survive the move and have to be re-checked, not assumed.** Every link and image target must stay **absolute**, because PyPI serves the long description without the repository and `docs/` is excluded from the sdist. The badge block is **duplicated on purpose** in `docs/badges.rst`, which the docs `include`; that copy stays reStructuredText, so the two stop being copy-pasteable and the duplication note in the maintenance rules has to say so. And the README **deep-links into `docs/` by Sphinx-derived anchor** — those targets stay `.rst` and the anchors do not move, so the links are unaffected, but confirm rather than assume.
- **The check that means anything is the rendered page, and the command changes.** `uv run --with readme-renderer python -m readme_renderer README.md -o tmp/readme.html` — `readme_renderer` renders Markdown as well, and rendering is the only thing that catches a target that does not resolve. `rstcheck` stops covering this file, which is the one piece of automation lost; nothing it reports about the README is worth keeping the format for, since it does not resolve roles or targets either.
- **Also update:** `pyproject.toml`'s `readme` field, `MANIFEST.in`, and the three README rules in `contributing/development/documentation-maintenance-rules.md`. `tests/test_package_contents.py` matches `README*` and needs no change. No test opens the file by path — `tests/test_documented_contracts.py` and `tests/test_coordinate_precision.py` name it in prose only, and those docstrings should be corrected while the name is being changed.
- **Not in the same pull request as a content change to the README.** The reflow half of this item is exactly the diff that a content change makes unreviewable.
- **Changelog sentence it stands under:** the README is written in Markdown, which is also what PyPI now renders. User-visible, since it changes the published project page.
- **Status:** open.
- **Last touched:** 2026-09-05 — filed with the format decision, and DOC-5 narrowed to hand the README over.
