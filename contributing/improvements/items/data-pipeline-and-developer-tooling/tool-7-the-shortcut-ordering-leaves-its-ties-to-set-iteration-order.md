# TOOL-7 — the shortcut ordering leaves its ties to set iteration order

- **Defect (build reproducibility and answer precedence):** `scripts/shortcuts.py`'s `process_single_hex` takes `list(cell.polys_in_cell)` — a `set` — and `optimise_shortcut_ordering` sorts it with two stable `sorted` calls. Where the sort key ties, the output order is therefore whatever order the set happened to iterate in, which is a CPython implementation detail of the insertion history rather than a property of the data.
- **Observed, 2026-09-06:** recompiling the shipped 2026c index from the same source with the candidate sets in sorted order produces **29 differing bytes across ~6 cells** — every one of them a tie.
- **The earlier claim that no answers move is false for current data.** In 2026d cell `84eeaa9ffffffff`, the inherited candidates `[786, 422]` are `Etc/UTC` and `Antarctica/Rothera`, each with five vertices. The geometric safety gate refuses cross-zone reordering there. Sorting the candidate ids therefore changes the final fallback from `Antarctica/Rothera` to `Etc/UTC`, moving every `TimezoneFinderL` answer in the cell and the full lookup's answer wherever neither candidate contains the point.
- **Polygon id remains a safe tie-break only within one zone.** It makes equal-size polygons reproducible without changing a zone answer. A cross-zone tie needs an index-independent precedence rule: numeric polygon and zone ids are properties of the data layout, while the [recorded semantics](../../decisions/shortcut-ordering-and-fallback-semantics.md) require answer precedence to be independent of the H3 index.
- **Decision needed:** Which index-independent rule should resolve equal legacy zone-size totals before future data builds? (1) Use the timezone identifier as the secondary sort key (recommended: the smallest rule, consistent with the existing identifier tie-break, but the next rebuild can move shared-border, overlap, fallback and `TimezoneFinderL` answers and therefore needs stability documentation and a data release); (2) use spherical zone area and then the timezone identifier (a geometry-based rule, but it takes part of PREC-1 before its broader precedence choice is settled); or (3) determinize equal-size polygons only within each zone and leave cross-zone ties unresolved (no cross-zone answer change, but shortcut binaries remain incompletely reproducible). Reversal requires rebuilding and republishing the data, and the affected-cell count beyond the witness above is not yet priced.
- **Size:** ~10 lines in `optimise_shortcut_ordering`, a test that permutes tied input, the result-stability documentation and the regenerated index in the next data release.
- **Status:** needs a deterministic cross-zone precedence rule; the implementation cannot remain a byte-only cleanup because it changes an unsafe cell's final zone.
