# DOC-1 — the prose documentation is hard-wrapped, so every small edit reflows a block

- **Location:** the hand-written prose under `docs/`, plus `README.rst` — `data_format.rst`, `1_usage.rst`, `alternatives.rst`, `benchmarking_methodology.rst`, `architecture.rst`, `2_use_cases.rst` carry the bulk of it.
- **Defect:** paragraphs are hard-wrapped at a fixed column, so a line break falls wherever the column ran out rather than where the sentence turns. **628 continuation lines across 11 files** end mid-clause. Changing one word reflows every following line of its paragraph, which makes the diff of a one-word correction indistinguishable from a rewrite: a reviewer cannot see what changed, `git blame` attributes the whole block to whoever last touched any of it, and two passes editing different sentences of the same paragraph conflict on lines neither of them meant to change. That last cost is not hypothetical here — concurrent sessions edit this tree, and a reflowed paragraph is a conflict with no semantic content to resolve.
- **Fix:** convert to semantic line breaks — one line per sentence, and per clause where a sentence is long enough that its clauses are edited independently. Rendered output is identical in both reStructuredText and Markdown, since both fold a single newline into a space, so this changes no published page. A one-word correction then shows as a one-line diff, and two passes editing different sentences of a paragraph do not touch the same lines.
- **The rule has to be written down in the same pass, or it drifts straight back.** `contributing/development/documentation-maintenance-rules.md` currently states no wrapping convention at all, which is why the tree has both styles: everything under `contributing/` is already one line per paragraph or bullet, and `docs/` is hard-wrapped. Converting without recording the convention buys one clean pass and then re-accumulates. Worth pricing a check alongside it — a hook that rejects a new continuation line ending mid-clause is cheap next to re-doing the conversion, though the heuristic needs care not to fire on tables, directives and code blocks.
- **Scope, and what is deliberately outside it:** the generated pages are not edited here — `benchmark_results_*.rst` and `data_report.rst` are written by `scripts/render_benchmark_reports.py` and the data report generator, so their line breaks are the generator's output and a finding there belongs against the generator. `CHANGELOG.rst` is already conformant where it is live: the unreleased section and every release back to 8.2.5 are one line per bullet, and only the historical tail below that is wrapped. Leave the tail alone — rewriting released history changes no reader's experience and costs the blame on it.
- **Why it is ranked here:** readability, which the ranking puts below duplication that will drift, and it is L-sized because it touches most of `docs/`. It earns its place rather than being pure tidying only through the conflict cost above, which is a real tax on concurrent passes. It is also the rare large item that is safe to split: any single file can be converted on its own, so a pass with capacity left can take `data_format.rst` (236 lines, by far the worst) and leave the rest.
- **Take it when nothing else is queued, and not in the same pull request as a content change to the same file.** A reflow diff and an edit diff in one review are exactly the reviewing problem this item exists to remove.
- **Status:** open.
