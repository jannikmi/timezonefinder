# TOOL-6 — the ruff version is pinned below 0.16

- **Location:** `pyproject.toml`, the `dev` group's `ruff<0.16`; `.pre-commit-config.yaml`, the `ruff-pre-commit` rev. The two are bound deliberately, so a bare `uv run ruff` cannot disagree with the hook, and raising one means raising both.
- **The pin costs nothing to raise. Measured 2026-09-06 at c27b452, and this corrects the figure the item and the [dependency decisions](../../decisions/benchmarking-tooling-and-dependency-decisions.md) used to carry.** `uvx ruff@0.16.6 check .` under this repository's own configuration reports **all checks passed**; `ruff@0.16.6 format --check .` would reformat **zero** files. The earlier "~145 sites, ~97 findings needing judgement" priced ruff 0.16's **widened default rule set** — `ruff check --isolated` on 0.16.6 does report 219 findings against 12 on 0.15.22 — but `[tool.ruff.lint] select` names `E4, E7, E9, F, B, RUF013` explicitly, and naming any `select` *replaces* the default rather than adding to it. The widened default never reaches this tree. **Adopting 0.16's defaults is a separate decision** that this repository's explicit `select` already declines by construction; do not re-merge the two.
- **Decided 2026-09-06 by the maintainer: option (2) — the improvement-pass boundary is relaxed for dev-tool pins specifically, and a pass may take this bump.** A pass may raise the `ruff` bound and the `ruff-pre-commit` rev together, and commit the lockfile lines that bump alone produces; every other dependency, the supported Python versions and the release version stay out of a pass's reach. The reason is recurrence: 0.17 brings the identical question back, and an answer that routes each dev-tool bump through the maintainer pays a session of attention for a diff that is one line plus a rev.
  - **Refused: (1) the maintainer raises the pin directly, boundary unchanged** — the contributor recommendation, on the grounds that the measurement had removed the strong argument for bending a boundary, since the bump now costs minutes rather than a session. The maintainer chose the recurring answer over the one-off one.
  - **Refused: (3) stay on the 0.15 line and re-price later** — it was a defer-a-growing-bill answer and the measurement shows no bill; meanwhile every rule released after 0.15 stays invisible and the gap grows each release.
  - **The known cost of the chosen option, recorded so a later pass does not read the exception wider than it is.** A boundary with an exception is a boundary that can be misread, and a lockfile change is the kind of thing the boundary exists to keep out of unattended work. The mitigation is that the exception is stated by *artifact* rather than by intent: the `ruff` bound, the `ruff-pre-commit` rev, and the lockfile lines those two produce. A pass that finds itself touching anything else has left the exception.
  - **Reversibility:** the pin is one line either way. The boundary relaxation is the expensive half — unrelaxing it does not retract what passes already did under it.
  - **Unpriced uncertainty:** ruff's *formatter* style can shift between minor versions. The zero-reformat result above is a snapshot of this tree on 0.16.6, not a guarantee for files written later or for 0.17.
- **Implementing this decision is two changes, and neither belongs to the maintainer-decision workflow that recorded it.** The boundary sentence in the [improvement-pass workflow](../../../workflows/run-one-improvement-pass.md) still forbids a pass from changing a dependency or the lockfile, and it has to gain the dev-tool-pin exception before a pass can act on this entry; that amendment and the bump itself belong to whoever takes this item.
- **Knock-on for [TOOL-5](tool-5-the-pylint-complexity-limits-are-a-threshold-argument.md):** 0.16 promoted `PLR0917` (too-many-positional-arguments) out of preview, so `--select PLR09` reports **20** sites on 0.16.6 against **15** on 0.15.22. Any threshold chosen from today's tree is measured against a rule set that the next ruff release can widen.
- **Status:** open.
- **Last touched:** 2026-09-06 — decided; the ~97-finding premise measured false and replaced.
