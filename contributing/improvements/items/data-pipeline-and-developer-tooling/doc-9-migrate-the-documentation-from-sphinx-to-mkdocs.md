# DOC-9 — migrate `docs/` from Sphinx to MkDocs, converting the prose in the same pass

- **Location:** all of `docs/`; `docs/conf.py`, `docs/Makefile`, `docs/make.bat`, `docs/requirements_docs.txt`, `readthedocs.yml`, `Makefile`'s `docs` target, `pyproject.toml`'s docs dependencies and `[tool.rstcheck]`, `.pre-commit-config.yaml`'s `rstcheck` hook, `scripts/reporting.py` (`render_rst_table`, `rst_title`, `compute_column_widths`), `scripts/render_benchmark_reports.py`, `contributing/development/documentation-maintenance-rules.md`.
- **Decision, not a proposal.** Taken 2026-09-06 by the maintainer and recorded in the [documentation source format decisions](../../decisions/documentation-source-format-decisions.md), which carry the options refused — MyST, the status quo, `pdoc` and the JavaScript-toolchain generators — and the PDF/ePub assumption that is the one thing which would reopen it. Do not re-argue the choice here; this entry is the work.
- **What it is:** MkDocs with Material for MkDocs and `mkdocstrings`, on Read the Docs' `mkdocs:` key instead of `sphinx:`. Every page becomes CommonMark: `!!! note` for the 28 admonitions, pipe tables for the 42 `list-table`s, fences for the 36 code blocks, relative links and heading anchors for the 98 `:doc:`/`:ref:` cross-references.
- **This item absorbs the four semantic-line-break slices, and that is why they were withdrawn.** [DOC-2](doc-2-convert-the-data-format-reference-to-semantic-line-breaks.md) to [DOC-5](doc-5-convert-the-remaining-prose-pages-to-semantic-line-breaks.md) reflowed exactly the files this rewrites, so the line breaks are set while the Markdown is written and cost nothing extra — the same argument that had already moved `README.rst` out of DOC-5 and into [DOC-7](doc-7-move-the-readme-to-markdown-with-semantic-line-breaks.md). **Converting without setting them would be the one unrecoverable mistake here**, because it spends the whole-file rewrite and leaves the hard wrap in place, and no second wholesale rewrite is coming. **718 continuation lines across the eleven hand-written pages**, counted 2026-09-05 by the method DOC-2 states; per-file counts are in those four withdrawn entries and are what to check the converted tree against.
- **Record the convention in the same pass**, which was DOC-2's other job: `contributing/development/documentation-maintenance-rules.md` states no wrapping rule at all, which is why the tree has two styles. That file also needs rewriting more broadly — most of its `rstcheck`, `readme_renderer` and `make docs` mechanics stop being true here.
- **The generated pages are the expensive half, and are not optional.** `docs/benchmark_results_*.rst` and `docs/data_report.rst` are **2,123 of the 5,332 lines** and are emitted, so the emitters convert rather than the files: `render_rst_table` becomes a pipe-table writer, `rst_title` an ATX heading writer, and `compute_column_widths` has no Markdown equivalent and is deleted. Then regenerate — per the [documentation maintenance rules](../../../development/documentation-maintenance-rules.md), `scripts/reporting.py` rewrites the data report from the packaged binaries in seconds, while the four benchmark pages must be re-rendered from the **stored JSONs behind the committed reports**, never re-measured on a contributor machine. Confirm the JSONs first by re-rendering before the change and checking `git diff docs/benchmark_results_*.rst` is empty.
- **Pipe tables cannot do what those tables do.** No `:widths:`, no multi-line cells. Where a benchmark table needs either, emit a raw HTML `<table>` — Markdown passes it through, and it keeps the emitter honest about which pages actually need it rather than degrading all of them.
- **The API page is the one real integration risk, and it is 60 lines.** `docs/4_api.rst` holds all 14 autodoc directives; they become `::: timezonefinder.timezone_at` blocks. The catch is that this package's docstrings are Sphinx-style — **310 `:param:`/`:return:` field lines** across `timezonefinder/*.py` — so `mkdocstrings` needs `griffe`'s `sphinx` docstring parser, which is supported but the least-travelled of the three it offers. **Verify this page renders before converting anything else**; if the Sphinx parser disappoints, converting the docstrings to Google style is a separate item, not a reason to abandon this one.
- **It is big-bang and there is no half-way state.** MkDocs cannot read reStructuredText, so this is one pull request converting 5,332 lines, and the review problem is real. Split the *commits* — infrastructure, generated emitters, then prose page by page — so the diff can be read in pieces even though it must land at once.
- **What lands with it:** delete `docs/conf.py`, `docs/Makefile`, `docs/make.bat` and `[tool.rstcheck]`; add `mkdocs.yml` carrying the four captioned sections `docs/index.rst`'s toctrees currently declare; drop the `rstcheck` hook — it will have nothing left to lint once `README` and `CHANGELOG` have moved under DOC-7 and DOC-8, and if either is still `.rst` the hook stays until it is not. Add `mkdocs --strict` to the docs build so a broken cross-reference fails it; that is a capability `rstcheck` never had and the reason the hook's loss is not a regression.
- **Do not take it while another `docs/` change is open**, for the reason every slice in the withdrawn family gave: a wholesale rewrite and a content change in one review are unreadable together. This is the largest instance of that problem, not an exception to it.
- **Changelog sentence it stands under:** the documentation is built with MkDocs and written in Markdown. User-visible — it changes the published documentation site, and drops the PDF and ePub downloads.
- **Status:** open.
- **Last touched:** 2026-09-06 — filed when the maintainer chose MkDocs, absorbing DOC-2 to DOC-5.
