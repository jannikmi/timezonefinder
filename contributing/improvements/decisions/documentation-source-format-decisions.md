# Documentation source format decisions

Do not re-propose these settled or refused options without new evidence.

- **`README` and `CHANGELOG` move to Markdown; the hand-written `docs/` pages stay reStructuredText.** Decided 2026-09-05 by the maintainer, who asked whether the documentation could be migrated to Markdown in full. It can — Sphinx reads Markdown through `myst-parser`, and the two suffixes coexist in one build indefinitely, so none of this is a one-way door — but the answer splits by file, because what Markdown buys differs by two orders of magnitude across them. [DOC-7](../items/data-pipeline-and-developer-tooling/doc-7-move-the-readme-to-markdown-with-semantic-line-breaks.md) carries the README and [DOC-8](../items/data-pipeline-and-developer-tooling/doc-8-move-the-changelog-and-its-fragments-to-markdown.md) the changelog; the `docs/` half is refused below and is not an open item.
- **Why `docs/` is refused: MyST respells reStructuredText's markup rather than removing it.** Counted across `docs/`, `README.rst` and `CHANGELOG.rst` on 2026-09-05: 42 `list-table`, 36 `code-block`, 28 `note`, 21 `image`, 14 autodoc directives, 4 `toctree`, 3 `include`, and in roles 73 `:doc:`, 25 `:ref:`, 18 `:sup:` and 11 `:meth:`/`:func:`. Every one of those survives the move as `` ```{list-table} `` and `` {doc}`…` ``. The prose gets easier — no title underlines, no indentation-sensitive blocks — and the structural third of the pages gets no easier at all. Those two files are almost entirely prose and almost entirely free of both; the `docs/` pages are the opposite, which is the whole of the split.
- **Two things `docs/` would actively lose.** GitHub renders `.rst` natively, directives included, so `docs/` is readable in the repository today; under MyST those 42 tables and 28 notes render as literal grey code blocks in GitHub's file view, and only Read the Docs stays correct. And the `rstcheck` hook has no Markdown equivalent — the [documentation maintenance rules](../../development/documentation-maintenance-rules.md) record that it catches a directive running into the block after it, which is exactly the defect that reached `master` while `docs/` was excluded from it. Markdown linters check style, not directive structure, and MyST is quieter about that class of mistake rather than louder.
- **And a third of `docs/` is not hand-written at all.** `docs/benchmark_results_*.rst` and `docs/data_report.rst` are ~2,100 lines emitted by `scripts/render_benchmark_reports.py` and `scripts/reporting.py` (`render_rst_table`, `rst_title`, `compute_column_widths`). Converting them means rewriting the emitters, updating their artifact tests and regenerating every committed measurement — and then either emitting MyST `list-table`, which keeps the proportional-width logic and gains nothing, or pipe tables, which lose column widths and multi-line cells.
- **Refused, and why each loses.** *Convert everything, `docs/` included* — pays the emitter rewrite and the GitHub-rendering loss for markup that is respelled rather than removed. *Convert only the hand-written `docs/` prose and leave the generated reports as `.rst`* — the cheapest version of the full migration and still the wrong trade: it keeps the GitHub regression and the `rstcheck` loss on the pages that carry the cross-references, and leaves the tree split by whether a page happens to be generated, which is not a distinction an author can see. *Leave `README` and `CHANGELOG` on reStructuredText too* — declined by the maintainer, who does not want to write the format; there is no technical case for it, since PyPI has rendered Markdown long descriptions for years.
- **What would change it:** a Markdown checker that validates MyST directive structure the way `rstcheck` validates reStructuredText, or GitHub rendering MyST directives in its file view. Either removes one of the two losses above; both would make the `docs/` half worth re-pricing. A wish to be rid of reStructuredText is not new evidence, because the counted markup above is what MyST does not remove.
- **The mixed tree is a known, accepted cost.** `.rst` and `.md` side by side in one repository is a small ongoing tax on every author — human or agent — who has to know which syntax a file wants. It was weighed against converting `docs/` and lost, because the tax is paid per edit and is small, while the two losses above are permanent. `contributing/` is already Markdown, so the tree is mixed today regardless.
