# Ruff version and lint-rule selection decisions

Do not re-propose these settled or refused options without new evidence. `[tool.ruff.lint] select` in `pyproject.toml` is the rule set they bind; `tests/test_lint_configuration.py` probes that each selected rule still fires.

- **`ruff` is no longer held below 0.16, and the hold's stated cost was wrong.** The `dev` group's bound and the `ruff-pre-commit` rev are still bound to each other on purpose, so a bare `uv run ruff` cannot disagree with the hook and raising one means raising both. What changed is the price: the hold recorded ~145 rewritten sites and ~97 findings needing judgement, and measurement on 2026-09-06 at c27b452 found **zero** of either — `uvx ruff@0.16.6 check .` under this repository's configuration passes, and `ruff@0.16.6 format --check .` would reformat nothing. The old figure priced ruff 0.16's **widened default rule set**, which this tree never sees: `[tool.ruff.lint] select` names `E4, E7, E9, F, B, RUF013` explicitly, and naming any `select` replaces the default rather than extending it. The generalisable mistake, worth not repeating for the next tool bump: **`--isolated` measures the tool's opinion, not this repository's cost.** Adopting 0.16's defaults remains a separate, unmade decision; do not re-merge it with a version bump. **The improvement-pass boundary is relaxed for dev-tool pins specifically** (decided 2026-09-06, [TOOL-6](../items/data-pipeline-and-developer-tooling/tool-6-the-ruff-version-is-pinned-below-0-16.md)): a pass may raise the `ruff` bound and the `ruff-pre-commit` rev together and commit the lockfile lines that bump alone produces, because 0.17 returns the same question and routing each dev-tool bump through the maintainer spends a session on one line. The exception is stated by artifact, not by intent — a pass touching any other dependency, the supported Python versions or the release version has left it.

- **`PLR09xx` complexity limits are refused; function size stays a review judgement.** Decided 2026-09-06 ([TOOL-5](../items/data-pipeline-and-developer-tooling/tool-5-the-pylint-complexity-limits-are-a-threshold-argument.md)), against 15 sites at ruff's defaults. The generalisable part, worth applying to the next lint family proposed on a count: **a threshold rule reports that a function is larger than a number nobody here chose, not that anything is wrong** — so the count is not the argument, and three things beat it. 10 of the 15 sites are in `scripts/` and `benchmarks/` rather than the shipped package. The two widest, `pt_in_poly_clang_packed` and `pt_in_poly_packed` at 11 arguments each, are flat scalar signatures *because* that is the cffi and njit calling convention, so the rule needs a permanent suppression on its own worst offenders. And the remaining margins are one to six over the limit. Setting limits above the tree instead was refused as well: the number would be read off today's worst function, and since a pass may now raise the ruff pin unattended, an unattended bump re-scopes it — 0.16 promoting `PLR0917` out of preview takes `--select PLR09` from 15 sites to 20. Re-propose only by naming a function that was actually hard to change, never by recounting the sites.

- **`A001`, `A002` and `PLW2901` are refused; each flags an idiom this tree uses on purpose.** Decided 2026-09-26 by an improvement pass, against 12 sites on ruff 0.15.22 — up from the 7 the proposal measured on 2026-09-06 at c27b452, all of the growth `PLW2901` in newer tests and in `scripts/shortcut_ordering.py`. Every site was read and none is a defect. Of the 4 builtin-shadowing sites, `docs/conf.py`'s `copyright` is the name Sphinx reads, and `input` in `tests/cli_test.py`'s `run_cli` and `tests/test_lint_configuration.py`'s `_ruff` mirrors the `subprocess.run` keyword each passes through, so the family would need permanent suppressions on three of its four findings; the fourth, the loop variable `input` in `tests/auxiliaries.py`'s `proto_test_case`, is renamable but is not a reason to adopt a rule the other three contradict. All 8 loop-variable sites normalise the value they were handed — `float()`, `utils.validate_coordinates`, `.copy()` before a shuffle, `refine` of a candidate order, an ocean zone mapped to `None` — where a second name would leave the unnormalised one in scope to be used by mistake, which is the bug the rule exists to catch. Bare `A` or `PLW` would select far more than these rules and was not measured as an alternative. Re-propose only with a site where the shadowing or overwrite actually caused a wrong value, never by recounting the sites.
